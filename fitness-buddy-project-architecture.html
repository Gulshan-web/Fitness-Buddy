💪 Fitness Buddy

Project Architecture · IBM Granite AI · Full-Stack Web App

🌐 Layer 1 — Browser / Frontend (Client Side)
HTML
index.html
Single-Page App shell. All 8 pages defined here — shown/hidden by JavaScript. Never reloads.
📄 366 lines · 8 pages · 1 file
CSS
style.css
Red & Black gym theme. All colours controlled by CSS variables in :root. Fully responsive.
🎨 688 lines · 1 variable block controls everything
JavaScript
app.js
All frontend logic — navigation, chat UI, workouts, nutrition, habits, dashboard, AI fallback.
⚙️ 780+ lines · No frameworks · Vanilla JS
What runs here: Page navigation · User profile form · Chat interface · Workout filter · Habit tracker · Dashboard · localStorage read/write
POST /api/chat → JSON payload · GET / → HTML · GET /style.css → CSS
🖥️ Layer 2 — Backend Server (Runs on your machine)
Python
app.py
Flask server. Serves static files. Proxies IBM Granite requests with IAM auth. Caches tokens.
🐍 121 lines · 3 routes: / · /api/chat · /api/health
Node.js
server.js
Alternative Node.js backend. Same job as app.py — use either one, not both.
🟢 120 lines · http module · No npm needed
Text
requirements.txt
Python dependencies for app.py. Install once with pip.
📦 3 packages: flask · requests · python-dotenv
Secret
.env
IBM API key, project ID, model ID, endpoint URL. Loaded at startup. Never committed to git.
🔐 7 lines · gitignored · env.example is the safe copy
Why a backend? Browsers block direct calls to iam.cloud.ibm.com (CORS). The server fetches the IAM token server-side, caches it, and forwards requests to IBM Granite securely.
POST + Bearer token → IBM Granite · POST apikey → IBM IAM
☁️ Layer 3 — IBM Cloud (External AI Services)
IBM IAM
IAM Token Service
Exchanges your API key for a short-lived Bearer token (1 hour). Called server-side only.
🔑 iam.cloud.ibm.com/identity/token
IBM Granite
ibm/granite-4-h-small
The AI model that generates all fitness coaching responses, personalised to user profile.
🤖 us-south.ml.cloud.ibm.com · Project: db036f3d
Model input: System prompt (with user profile) + chat history → Model output: Personalised fitness advice, meal plans, workout routines
💾 Layer 4 — Client Storage (Browser localStorage)
localStorage
fb_profile
User profile JSON — name, age, goal, level, workout time, food prefs, health notes.
👤 Persists across sessions · No login needed
localStorage
fb_habits
Daily habit state keyed by date — workout ✓, water intake, meals, sleep hours, steps.
📅 Keyed by YYYY-MM-DD · Used for streaks
No database needed. All user data is stored in the browser. The dashboard and habit streaks read directly from localStorage on every page load.

▶️ How to Run

🐍 Python (Recommended)
1. cd fitness-buddy
2. pip install -r requirements.txt
3. python app.py
4. http://localhost:3000
🟢 Node.js (Alternative)
1. cd fitness-buddy
2. (no install needed)
3. node server.js
4. http://localhost:3000
